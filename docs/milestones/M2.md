## A. Summary

- **Kernels.**
  - `data/kernels/kernels.json` records the four NAIF kernels: `naif0012.tls`,
    `pck00011.tpc`, `gm_de440.tpc` and `de440s.bsp`. For each it gives the URL, purpose,
    size, SHA-256 (trust on first use, 2026-11-12), the NAIF MD5 where published (de440s:
    matches `aa_checksums.txt`), the server's Last-Modified time and the retrieval time.
  - `helioswarm fetch-kernels` (or `scripts/fetch_kernels.py`) downloads into
    `$HELIOSWARM_KERNEL_DIR`. It is idempotent: each file goes to a temporary file, is
    verified, and only then is renamed. It refuses a mismatching download, and it refuses
    (without overwriting) a mismatching existing file.
  - `helioswarm.kernels.KernelSet.loaded()` is the only way kernels are loaded:
    - it verifies the files;
    - it requires an empty SPICE pool (no nesting, no foreign kernels);
    - it furnishes the files in manifest order;
    - it unloads and `kclear`s them on exit;
    - it yields a `LoadedKernels` handle that every SPICE-backed function checks.
  - Provenance records for the run manifest come from `LoadedKernels.provenance` and
    `KernelManifest.sha256`.
  - CI caches the kernels keyed on the hash of `kernels.json` and verifies them.
- **Time** (`helioswarm.timescale`).
  - UTC → TDB uses `str2et` on an explicitly UTC-labelled string; TDB → UTC uses `et2utc`.
  - `Epoch` and `TimeGrid` are frozen and carry `scale="TDB"`. Output grids are uniform in TDB.
  - Cross-checks: against IERS Bulletin C plus the USNO TDB formula, 3.6e-7 s; against
    astropy/ERFA, 2.7e-5 s.
- **Ephemeris** (`helioswarm.ephemeris`).
  - The `EphemerisProvider` protocol returns `EphemerisState` objects (J2000/SSB, SI, TDB,
    with `source_kernel_ids`).
  - `SpiceEphemeris` uses `spkgeo` (km → m) and `bodvrd` GM values (km³ → m³). It checks
    coverage per body, along the SPK segment chain, with a clear error.
  - `AnalyticEphemeris` is a kernel-free test double: a uniformly moving Sun and a circular
    Earth.
  - Origin shifts Sun ↔ SSB and a cubic-Hermite ephemeris cache are also provided.
  - de440s agrees with JPL Horizons (DE441) to 5.4 cm.
- **Frames.** `frames.spice_rotation_matrix` (SPICE `pxform`) agrees exactly with the M1
  obliquity rotation.
- **SRP** (`helioswarm.srp`): radial cannonball / Sun-facing plate,
  `a = (S_1AU/c)(AU/r☉)² C_r (A/m) ŝ`.
- **L1 propagator** (`helioswarm.propagate`).
  - It integrates a test particle under the prescribed DE440 bodies (+ SRP) with DOP853, in
    heliocentric coordinates with the direct and indirect terms of exactly the modelled bodies
    (M2 review; the barycentric form remains as a guarded comparison path). Input/output
    states are J2000/SSB. rtol and atol come from new config fields;
    `max_step = time.integrator_step_s`.
  - Outputs use dense output; epochs before the initial epoch are integrated backwards.
  - Diagnostics: nfev, success, message, segments, a heliocentric two-body energy drift and
    the measured Hermite-cache error per body; `assess_l1_run` adds the step-convergence and
    SRP-effect report (M2 review).
  - `SatelliteState` holds the J2000/SSB state plus `ForceModel`; it is built from the
    config: ECLIPJ2000 elements → J2000 → plus the Sun's SSB state.
- **Validated by:**
  - Sun-only L1 equals L0 (6.7e-4 m over a year with a moving analytic Sun; 7.7e-4 m with the
    real de440s Sun after the M2 review fix);
  - SRP equals Kepler with GM☉ − k (5.8e-3 m);

  - REBOUND IAS15 (two-body 7.7e-4 m; full N-body 1.03 m after the M2 review fix, 565 m
    before it).
- **Exit criteria met.**
  - The kernels are fetched and verified.
  - 55 `spice`/`xcheck` tests ran and passed (0 skipped); 62 after the M2 review.
  - The MVP satellite initial state is built in J2000/SSB

## E. Assumptions and equations implemented

All equations, validity ranges and references are in `docs/model_assumptions.md`, section
"M2". In short:

- **Time.** `TDB = UTC + ΔAT(LSK) + 32.184 s + K sin(M + EB sin M)` (SPICE `str2et`; NAIF Time
  Required Reading). Epochs are TDB s past J2000, and grids are uniform in TDB.
- **Ephemeris.** States are geometric `spkgeo` states in J2000/SSB, km → m. GM comes from
  `gm_de440.tpc` (`bodvrd`), km³ → m³. The kernel GM is authoritative whenever SPICE is used;
  `constants.GM_SUN_M3_S2` is the same DE440 value to 2 ulp.
- **Initial state.** `r_SSB = R_x(−ε₀)·r_ECL(elements; GM☉) + r_☉/SSB(t₀)`, and likewise for
  velocity.
- **SRP.** `a = (S_1AU/c)(AU/r☉)² C_r (A/m) ŝ`, which equals `k (r − r☉)/|r − r☉|³` with
  `k = (S/c)AU²C_r(A/m)`. It is the cannonball / Sun-facing-plate model (Montenbruck & Gill
  2000, §3.4), without shadowing, attitude or Poynting–Robertson terms.
- **L1** (PDF §6.2, heliocentric frame with the correct indirect term; M2 review):
  `r̈ = −(μ☉ − k) r/|r|³ + Σ_{j≠☉} μ_j [(R_j − r)/|R_j − r|³ − R_j/|R_j|³]` with r and R_j
  relative to the Sun, output `r + r☉(t)` in J2000/SSB; DOP853 (Hairer, Nørsett & Wanner
  §II.10). The barycentric form `Σ_j μ_j (r_j − r)/|r_j − r|³ + a_srp` is a comparison path
  restricted to complete planetary sets.
- **Ephemeris cache.** Piecewise cubic Hermite, error ≤ h⁴/384·max|x⁗| (de Boor).

## F. Known limitations and next milestone

### Deviations from the plan, and the choices behind them

1. **Sun-only L1 and the real Sun (revised in the M2 review).** The first implementation
   integrated the PDF equation in the barycentric frame with the DE440 Sun, so Sun-only L1
   carried the Sun's planet-driven reflex acceleration without the planets' direct pull and
   departed from L0 by 2.2e8 m in a year; that was wrongly presented as physics. L1 now
   integrates heliocentrically with consistent direct and indirect terms, so Sun-only L1
   equals L0 with the SPICE Sun (7.7e-4 m) and any body subset is physically consistent. See
   "Review outcomes" below.
2. **Earth–Sun reference.** The brief allowed reference values "ONLY if you can obtain them
   reproducibly". The JPL Horizons API was reachable, so de440s is checked against Horizons
   (DE441) vectors at 6 epochs to 1 m. The query URL and the verbatim numbers are in the test.
   The brief's suggested fallbacks were implemented as well: annual extremes and period, and
   astropy builtin (ERFA epv00). The epv00 tolerance is its *documented* accuracy (11.2 km).
   The brief's "~1e-6 relative" is not achievable with epv00 in position (measured 7.1 km =
   4.7e-8 relative in distance, but up to 7 km in the vector), so the documented bound is used
   instead.
3. **Extra body.** `EARTH BARYCENTER` (NAIF 3) is supported by the provider. It is used by the
   EMB perihelion-period and EMB-identity tests. It is not a default perturber, and
   `ForceModel` rejects it together with EARTH/MOON (double counting).
4. **Config additions.** `orbit.perturbing_bodies` (the brief's "bodies selectable from
   config") and `time.ephemeris_cache_step_s` were added besides the rtol/atol fields. The
   MVP config hash changed from `37999a09…5fc2` to `f2d46ab0…7561`; removing exactly the five
   new keys reproduces the M1 digest. The M2 review added `frames.ephemeris_kernel_set`
   (hash `b12c5a85…9c18`; removing that key reproduces `f2d46ab0…7561`). `schema_version`
   stays at 1.
5. **Performance.** The MVP's `integrator_step_s = 300 s` costs about 34 s per simulated year
   (about 50 s with the heliocentric right-hand side of the M2 review; 1.3e6 RHS evaluations,
   mostly scipy's per-step Python overhead). A 1-day cap gives the same trajectory to 2.5 cm
   (4.6 cm after the review) in 0.7 s (1.4 s). The configured value is kept and the cost is reported.
   Changing the MVP config is a scenario decision, not an M2 one.
6. **CLI.** Only `fetch-kernels` was added, as the brief allows.

### Limitations

- **SPICE scope.** The pool is process-global and not thread-safe, so there is one loaded scope
  per process. Parallel sweeps (M8) must use processes.
- **Leap seconds.** The LSK has no leap second after 2017. Future leap seconds would shift UTC
  epochs by 1 s each until the LSK is updated.
- **Omitted forces.** Not modelled: relativity (1PN: 5.6e4 m/yr along-track at 1 au, closed
  form 2β₁PN·n·t·a with β₁PN = 3GM☉/(rc²), confirmed by a direct integration; M2 review),
  asteroids, Pluto, planetary and solar oblateness, SRP shadowing, attitude-dependent SRP and
  Poynting–Robertson drag.
- **L0 at the SSB.** L1 is the only propagator wired to the config (`propagate_l1_from_config`
  rejects `two_body_kepler`). An L0 trajectory at the SSB needs `shift_trajectory_origin` and
  is wired in M6.
- **`fetch-kernels` defaults.** The default manifest path assumes a source checkout
  (`data/kernels/kernels.json`). A wheel install must pass `--manifest`.
- **Horizons drift.** The Horizons test values were retrieved once. If JPL changes Horizons'
  default ephemeris, re-running the query may give slightly different numbers. The embedded
  values remain the test reference.
