## A. Summary

- **Schema** (`config.py`). `orbit.phase_reference` = `absolute` (default; unchanged meaning and
  numbers) or `earth_relative` (the angle is the heliocentric ecliptic longitude offset from the
  Earth's at the element epoch, + ahead of the Earth; resolved from DE440 at run time;
  rejected for polar orbits). Optional `constellation` section: rings (elements inheriting
  from `orbit`, `n_satellites`, `even`/`random` phases with `phase_offset_deg` and
  `phase_span_deg`, per-ring phase reference and technology overrides — collector area,
  transmitter aperture, electrical-to-beam efficiency, pointing sigma — each satellite validated
  as a full single-satellite configuration), scheduler (`greedy_max_power` | `optimal_assignment`,
  optional duty cycle, `retarget_model = instantaneous`), mass proxy. Receiver capacity:
  `receiver.max_simultaneous_beams` and per-site overrides of beam slots, input-power and
  heat-rejection limits. The MVP configuration hash was re-pinned; deleting exactly the new keys
  restores the M6 digest (test). Two pre-existing "explicitly set but ignored" rules rejected
  the resolved dump of any L0 configuration (default-valued `perturbing_bodies` and L1
  integrator fields written explicitly); they now accept default-equal values (test).
- **Orbits** (`propagate.py`). `resolve_orbit_phase`, `earth_ecliptic_longitude_rad`,
  `argument_of_latitude_for_longitude_rad`; `propagate_l1_stacked` integrates many test
  particles as one 6N-state DOP853 solve with tolerances divided by √N (a heuristic: DOP853's
  error norm is not separable by satellite, so this does *not* guarantee each satellite's solo
  criterion; agreement is measured, D), ≤ 100 satellites per stack at rtol 1e-12, a stack of
  one = the solo integrator bit for bit; L0 closed form per satellite.
- **Stage A, link candidates** (`constellation.evaluate_links`). Per satellite: orbit,
  illumination, M4 solar/thermal; per satellite × site: access (retarded time, occultation,
  elevation, Sun avoidance), atmosphere, beam (M5 per-pair reference by default, or the batched
  kernel per block of satellites: `numpy_batch`, `jax`) and the single-link availability bits
  and budget of `system.site_link_budget` — the function the single-satellite run now also
  calls (refactored out of `run_single_satellite`, numbers unchanged). Receiver limits are not
  applied per link.
- **Scheduler** (`scheduler.py`). Per epoch: beam exclusivity, beam slots, summed peak-irradiance
  interlock (incoherent sum), summed receiver input/heat limit (clip), optional causal duty
  cycle. `greedy_max_power` with the total order (power desc, satellite, site);
  `optimal_assignment` (best-link bound and `linear_sum_assignment` exact; `milp` with
  `mip_rel_gap = mip_abs_gap = 0`, optimal to the HiGHS feasibility tolerances; a repaired
  epoch is feasible but not certified optimal), verified against brute-force enumeration. Canonical input order → deterministic and permutation
  invariant. Decision reasons `SCHEDULER_NOT_SELECTED`, `RECEIVER_CAPACITY`, `DUTY_CYCLE`
  (new `Unavailability` bits 10–12).
- **Stage B, network** (`constellation.finish_constellation`). `P_grid,j = min(Σ P_captured,
  L_j) η_rx η_grid`, network = Σ_j; per-satellite pro-rata shares; satellite and link reason
  breakdowns. A one-satellite constellation reproduces the M6 run bit for bit (test). Added in
  the review: the unconstrained baseline (every satellite on its best link, no site capacity:
  separates placement from capacity), an independent recount of the network P_grid, and the
  reception-time reconstruction that bounds the **emission-epoch aggregation** (a named
  approximation: beams of one emission epoch are summed and limited together although they
  arrive at the receiver up to the spread of their light times apart).
- **Outputs** (`constellation_io.py`). `network.parquet`, `receivers.parquet`,
  `satellites.parquet`, optional chunked per-link detail (`links/part-*.parquet`, one row group
  per satellite, refused above a size cap before writing), `summary.json`
  (`ConstellationSummary`: network/receiver P_grid statistics, availability, outages, counts,
  totals of collector/radiator/aperture area and mass proxy, power per collector area and per
  mass, end-to-end efficiency, stage energies, unavailability breakdowns, double-counting check),
  `manifest.json` (written last), figures from the saved tables, `logs/run.log`. Array-task link
  files (`linkset_<i>_of_<n>.npz`) with a checked merge.
- **CLI / sweep**: `helioswarm run` dispatches on the `constellation` section; `--chunk-index
  --chunk-count --candidates-dir` (stage A as array tasks), `--candidates-dir` (merge +
  schedule), `--link-detail [--link-detail-max-gb]`, `--backend numpy|numpy_batch|jax`;
  `helioswarm plot` redraws constellation figures; `sweep` accepts constellation keys and
  collates constellation summaries.
- **Configs**: `constellation_demo.yaml` (N = 10), `constellation_demo_n1000.yaml`,
  `constellation_demo_sweep.yaml` (N 1/10/100 × even/random × greedy/optimal), and
  `constellation_n1_mvp.yaml` (the MVP as a one-satellite ring).
- **`opt` extra** for M8: pymoo 0.6.2 and SALib 1.6.0 (wheels on py3.12; locked).

Findings, stated plainly:

- **One satellite 30° ahead of the Earth delivers 20.7 kW** mean (12× the MVP's 1.75 kW
  at ~70° behind: range 0.52 au instead of ~1.15 au). With three sites 120° apart in longitude
  the network is never in outage, although each site alone sees the satellite only ~33 % of the
  time (366 outages per site, longest 17–18 h).
- **Placement and capacity, separated** (review finding 5). The single "even" satellite sits
  in the most favourable slot (+30°, shortest range): a randomly placed one (p0002, at +85°)
  delivers 6.8× less. The placement-neutral baseline is the mean over the 1000 evenly phased
  satellites of the N = 1000 run with unlimited receivers: **3.96 kW per satellite
  (0.396 W/m²)**, not 20.7 kW. Without site capacity the delivered power per collector area is
  set by geometry alone: 2.07 (N = 1 at the best slot) → 0.454 → 0.398 → 0.396 W/m² for
  N = 1, 10, 100, 1000 (even), i.e. it is flat from N = 10 on once the ring is sampled. The
  delivered values 2.07 → 0.44 → 0.17 → 0.028 W/m² fall further only because of receiver
  capacity: capacity loss 0, 2.5 %, 56 % and 93 % of the unconstrained energy.
- **Receiver capacity is the bottleneck from N ≈ 100.** With 20 beam slots (8 + 8 + 4) and one
  200 kW site, ~15–17 satellites deliver at a time; 84 % (N = 100) and 98 % (N = 1000) of
  satellite-time is lost to `RECEIVER_CAPACITY`; site `site_lon120w` saturates 4 % (N = 100)
  and 30 % (N = 1000) of the time (77 MWh clipped at N = 1000 under greedy).
- **Even vs random phases** (PDF §11.2): even phases deliver 49 % more at N = 10 (random phases
  leave the near-Earth arcs sparsely populated; also without receiver limits, 0.454 vs
  0.317 W/m²); at N = 100 the difference vanishes (0.2 %) because the receivers, not the
  satellites, limit the network. All of this is within the assumed 300° arc that keeps every
  satellite ≥ 30° from the Earth (a scenario choice, not a validity limit; the near-Earth
  slots would deliver more).
- **Greedy vs exact optimum**: the optimum delivers 0.4–0.9 % more energy and never less at any
  epoch (checked on the saved `network.parquet` of each pair: min(optimal − greedy) = 0 W,
  strictly more in 1033–2683 of 8101 epochs); it needed the MILP in 360 (even) / 126 (random)
  epochs at N = 100 (the 200 kW limit binding), the Hungarian assignment otherwise.
- **No double counting**: every summary's check passed. The independent evidence is the
  recount of the network energy from the satellite assignments and link powers (relative
  difference 0 in every run), the sum of the per-satellite shares (≤ 1.3e-16) and scheduled
  beams = active satellites at every epoch, plus the sum-of-independent-runs and scheduler
  exclusivity tests. (Network energy = Σ receiver energies, ≤ 2.2e-16, is only a consistency
  check: the network column is that sum by construction.)
- **Emission-epoch aggregation** (named approximation, review finding 1): the beams summed at
  one site in one emission epoch have light-time spreads up to 758 s (N = 10; median 460–509 s
  per site), 353 s (N = 100) and 58 s (N = 1000, where only the nearest satellites get slots;
  median 7.5–17.6 s), against the 3896 s step. Reconstructed in reception time, the accepted
  energy changes by ≤ 1.1e-4 relative per site (the clipping 200 kW site at N = 1000; the
  others ≤ 3e-7, the light-time rate) and ≤ 1.9e-5 over the network (N = 1000: −1.9e-5), and
  no density interlock is set. The **beam-slot limit
  is exceeded transiently** at the receiver after reassignments (an outgoing far beam is still
  arriving when an incoming near beam starts): up to 10/8, 9/8, 6/4 beams at N = 10 and
  16/8, 16/8, 8/4 at N = 100 and 1000, for 0.01–0.6 % of each site's time (N = 10:
  0.01–0.42 %, N = 100 even: 0.46–0.61 %, N = 1000: 0.07–0.09 %). Energies are unaffected; a receiver would need
  make-before-break guard slots for these transients.

## E. Assumptions and equations implemented

Full text in `docs/model_assumptions.md` ("M7: Constellation").

- Earth-relative phase: `λ_sat = λ_E(t₀) + φ` with the geometric heliocentric ECLIPJ2000
  longitude of NAIF 399; `u = atan2(sin Δ·sgn(cos i), cos Δ·|cos i|)`, `Δ = λ − Ω`;
  `ν = u − ω`.
- Ring phases `φ_k = offset + span·k/n` (even) or `offset + U_k`, `U_k ~ U[0, span)` from
  `Generator(project.seed)` (random).
- Stacked L1: tolerances × 1/√N (heuristic; per-satellite solo acceptance is *not* guaranteed
  by DOP853's non-separable error norm; agreement measured over one year, D); ≤ (rtol/1e-13)²
  satellites per stack.
- Per epoch: maximise `Σ_j min(Σ_i P_ij x_ij, L_j)` s.t. `Σ_j x_ij ≤ 1`, `Σ_i x_ij ≤ k_j`,
  `Σ_i d_ij x_ij ≤ D_j`, duty cycle; greedy (total order) or exact (best-link bound, Hungarian
  via `linear_sum_assignment`, MILP via `milp`, HiGHS, `mip_rel_gap = mip_abs_gap = 0`).
  Duty-cycle floors `N_w = ⌊window/Δt⌋`, `m = ⌊duty·N_w⌋` in exact decimal arithmetic.
- `L_j = min(P_max_input,j, Q_max,j/(1 − η_rx))`; `P_grid,j = min(Σ P_captured, L_j) η_rx
  η_grid`; network = Σ_j (independent, incoherent beams: powers add; PDF §11.3).
- Mass proxy `m = m_bus + s_col A_col + s_rad A_rad + s_tx πD²/4` (assumed values; radiator
  areal mass from `thermal.radiator_specific_mass_kg_m2`).
- Named approximations: instantaneous retargeting (events counted); coincident-peak upper bound
  of the summed density; myopic per-epoch scheduling; pro-rata per-satellite shares (summaries
  only); **emission-epoch aggregation** (receiver constraints and `P_grid,j` on the emission
  grid although the beams' light times differ; bounded on every run by the reception-time
  reconstruction: arrival intervals `[t_k + τ_k, t_{k+1} + τ_{k+1})`, `τ = range/c`, swept per
  site in continuous time).
- Unconstrained baseline `P_unc = η_rx η_grid Σ_i max_j P_captured,ij` (feasible links, no site
  capacity); capacity loss `1 − E_grid/E_unc`.

## F. Known limitations and next milestone

- **Capacity-limited by assumption.** The demo's receiver capacities (8/8/4 slots, one 200 kW
  site) are assumed scenario values; the N ≥ 100 results are dominated by them. They show the
  scheduler working, not a receiver design.
- **Clear sky everywhere, all year** (`scenario` atmosphere, one setting for all sites): network
  availability 1.0 is a weather upper bound; correlated weather and site diversity need M8a
  (ERA5).
- **Instantaneous retargeting** (named approximation): 1 096 (N = 1) to 34 080 (N = 1000)
  retarget events per year, each assumed free; a slew/acquisition model would reduce delivered
  energy.
- **Myopic scheduling**: each epoch is optimised alone (the duty-cycle rule is causal); no
  look-ahead. The demo sets no duty cycle.
- **Coincident-peak density bound**: the summed peak irradiance is an upper bound (no density
  limit is set in the demo, so it does not bind there).
- **Pro-rata per-satellite shares** under clipping are an accounting convention for the
  per-satellite table only.
- **Emission-epoch aggregation** (named approximation, review finding 1): receiver slot,
  power and density limits act on the beams of one emission epoch. In reception time the slot
  limit is exceeded transiently after reassignments (make-before-break by up to the light-time
  spread): 0.01–0.6 % of each site's time at N = 10–1000 (A, "Findings"); the accepted energy
  changes by ≤ 1.1e-4 per site and ≤ 1.9e-5 over the network. A reception-time scheduler (constraints on the receiver grid,
  exclusivity on each satellite's emission time, with guard times) is left for a later
  milestone; a real receiver would need make-before-break guard times or k_j + spare slots.
- **Mass proxy values are not sourced** (1 / 5 / 50 kg/m², 500 kg bus): W/kg numbers are
  illustrative until M8 varies them.
- **GPU path not used in production** (see D): the efficient GPU design (one capture pass over
  saved access points) is left for M8.
- The suite now takes 4.5 min on this node (target < 3 min): the M7 tests add ~35 s; the M2
  full-year L1 test remains the slowest single test. No M7 test is marked slow.
- The sweep's first attempt lost 52 min of four tasks to a node failure (requeued automatically;
  the resumable sweep reused the finished points).

Next: M7b GEO baseline (geocentric orbit through the same chain), then M8a (ERA5 weather,
economics) and M8 (optimisation and uncertainty; the `opt` extra is ready).
