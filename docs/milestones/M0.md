# M0: Scaffold (environment, package layout, config schema, `validate-config`, tooling, CI)

Status: implemented; reviewed (see "Review outcomes" at the end); all gates pass. Not committed
(a separate step commits).

## A. Summary

- **Environment.** A locked uv environment: `pyproject.toml` (hatchling, src layout,
  Python ≥ 3.11) and `uv.lock` with 66 packages. The `xcheck` extra (REBOUND 5.2.2, HCIPy 0.7.1)
  installs from wheels on CPython 3.12 (manylinux / py3-none-any), so nothing was dropped.
- **Cluster environment.** `scripts/cluster_env.sh` keeps the environment, caches, kernels and
  runs out of `/n/home05`.
- **Configuration schema** (`helioswarm.config`). A pydantic-v2 schema covers every section of
  the PDF §5 example: project, time, frames, orbit, collector, transmitter, receiver (sites
  list), thermal and models. It adds the sections and fields that later milestones need:
  `atmosphere`, `constants`, power-conditioning and optics efficiencies, illumination taper and
  waist, wavefront error, array spacing, pointing bias, receiver technology, maximum power
  density, Sun-avoidance angle, radiator area, PV emissivities, other heat load, limb margin,
  the Fraunhofer validity threshold and Earth/Moon occultation flags.
- **Field conventions.** Every field has:
  - a unit-suffixed name;
  - a documented default, or is required;
  - range validators;
  - `json_schema_extra = {provenance, description, unit, kind[, source]}`.
- **Model rules.** All models are frozen and strict (no silent coercion). They reject unknown
  keys (`extra="forbid"`) and NaN/inf. `schema_version` is checked.
- **Cross-field validators.** They report the dotted paths of every field involved.
- **Loading.** `load_config` aggregates readable errors as `path: message (got: value)`,
  including "did you mean" hints for unknown keys. The YAML loader fixes three PyYAML pitfalls:
  - `1.0e12` in the PDF example would otherwise be read as a string;
  - unquoted timestamps would otherwise become `datetime` objects;
  - duplicate keys would otherwise be silently overwritten.
- **Resolved output.** `dump_resolved_yaml` produces a resolved dump with all defaults explicit,
  and the dump is a fixed point under reload. `config_hash` is the SHA-256 of canonical JSON.
  `provenance_table` lists every leaf with its effective provenance (PDF §13.4) and supports
  per-run `provenance_overrides`.
- **CLI.** `helioswarm validate-config CONFIG [--show-provenance] [--write-resolved PATH]`
  exits 0 when the config is valid, 1 when it is invalid or unreadable, and 2 on a usage error.
  It is the only subcommand; there are no placeholders for later commands.
- **Tooling.** Ruff (line length 100, rule sets E, W, F, I, B, UP, N, NPY, RUF, C4, SIM, PT),
  mypy strict with the pydantic plugin, pytest (markers `slow`, `spice`, `xcheck`; strict
  markers; warnings are errors), pre-commit (basic hooks, ruff-check, ruff-format, local mypy)
  and GitHub Actions CI (Ubuntu, Python 3.11/3.12, `uv sync --all-extras --locked`, ruff, mypy,
  pytest).

## E. Assumptions and equations implemented

M0 has no physics models. The definitions it fixes are listed in `docs/model_assumptions.md`.

Constants:

| Constant | Value | Source |
|---|---|---|
| 1 au | 149 597 870 700 m, exact | IAU 2012 Resolution B2 |
| Nominal solar radius R☉ | 6.957×10⁸ m | IAU 2015 Resolution B3 |
| 1 day | 86 400 s | definition |

Sourced defaults:

| Field | Default | Source |
|---|---|---|
| `constants.solar_constant_1au_W_m2` | 1361 W m⁻² | IAU 2015 Resolution B3, nominal TSI |
| `thermal.space_temperature_K` | 2.725 K | Fixsen 2009, ApJ 707, 916 |
| `models.fraunhofer_max_fresnel_number` | 0.5 | Far-field distance R ≥ 2D²/λ, i.e. N_F = D²/(λR) ≤ 0.5 (IEEE Std 145-2013; Balanis, *Antenna Theory*, ch. 2) |

Validation rules:

- **Perihelion.** `a(1 − e) > R☉`.
- **Output grid.** `duration_days·86400` must be an integer multiple of `output_step_s`:
  `|duration_s − n·output_step_s| ≤ 8ε·duration_s` (float rounding only; changed in review).
- **Wavelength by mode.** Optical λ ∈ [1e-7, 2e-5] m (100 nm–20 µm). Microwave λ ∈ [1e-3, 1] m
  (300 MHz–300 GHz).
- **Beam model by mode.**
  - Optical allows {airy_far_field, gaussian_beam, fresnel_hankel}.
  - Microwave allows {aperture_far_field, fresnel_hankel}.
  - airy_far_field requires uniform illumination.
  - gaussian_beam requires truncated-Gaussian illumination with
    `a/w0 ≥ models.gaussian_beam_min_truncation_ratio` (default 2.5; added in review). Every
    truncated-Gaussian illumination needs `w0 ≤ a = D/2`.
- **Receiver technology by mode.** Optical requires laser_photovoltaic; microwave requires
  rectenna.
- **Radiator.** `T_limit > T_space`.
- **PV efficiency.** `η_min < η_max`, and `η_min ≤ η_ref ≤ η_max`.
- **Atmosphere.** The cloudy factor must be no better than the clear factor.
- **Orbit model.** `two_body_kepler` forbids perturbation and SRP flags. SRP requires
  `cr ∈ [1, 2]` and `area_to_mass_m2_kg`. The numerical propagator requires
  `integrator_step_s`.

Definitions fixed for later milestones:

- η_PV is relative to **absorbed** power (PDF §8.1).
- `optics_or_rf_efficiency` is not an aperture efficiency.
- The wavefront-error loss is `exp(−(2πσ_w/λ)²)` with σ_w the wavefront (not surface) error.
- `radiating_sides` is the number of faces of a thin plate that see space.

Config hash:

- It is the SHA-256 of `json.dumps(model_dump(mode="json"), sort_keys=True,
  separators=(",", ":"), ensure_ascii=True, allow_nan=False)`.
- It is invariant to key order, omitted vs explicit defaults, int vs float spelling and a `Z`
  suffix on epochs.
- It covers metadata as well (`project.name`, `seed`, `output_dir`), so it identifies the whole
  run definition.

## F. Known limitations and next milestone

### Deviations from the plan

1. **`constants.py` exists already.** The plan assigns it to M1. M0 needs the exact au and the
   nominal solar radius for the SI accessors and the perihelion check, so M0 creates it with only
   those constants and the day length. M1 extends it.
2. **Extra cache exports in `scripts/cluster_env.sh`.** The required exports are unchanged. Four
   cache redirections were added so that tool caches never land in `/n/home05`: `MYPY_CACHE_DIR`,
   `RUFF_CACHE_DIR`, `PYTHONPYCACHEPREFIX` and `PYTEST_ADDOPTS="-o cache_dir=…"`. All point to
   netscratch. The review added a fifth, `VIRTUALENV_OVERRIDE_APP_DATA`: pre-commit builds hook
   environments with virtualenv, which had written a 26 MB app-data cache to
   `~/.cache/virtualenv`. That directory (all 610 entries created by the M0 pre-commit run) was
   deleted. Before this, `.mypy_cache`, `.ruff_cache` and `.pytest_cache` (about 3.7 MB) had
   been created in the repo and were then deleted.
3. **The MVP config differs from the PDF example** by `schema_version: 1` and
   `receiver.technology: "laser_photovoltaic"`. Both are required by the schema. All other values
   are the PDF's own. (Before review, `schema_version` silently defaulted to 1 although this note
   said it was required. The review made it required with no default; this deviates from the
   milestone text `schema_version: int = 1`, so that an unversioned file is never read under a
   newer schema.)
4. **Test layout.** Tests use `--import-mode=importlib` with `pythonpath = ["tests"]`, and the
   shared helpers live in `tests/config_helpers.py`.
5. **Warnings.** `filterwarnings = ["error"]` turns every warning into a test failure. Later
   milestones must handle library warnings explicitly (for example ERFA "dubious year") rather
   than ignore them silently.

### Limitations

- **Staged validation.** Cross-section checks (beam vs mode, receiver technology vs mode,
  integrator step vs orbit model, provenance-override paths) run only after every section
  validates on its own, which is how pydantic works. A config with both a range error and a
  cross-section contradiction reports the contradiction after the range error is fixed.
- **Cross-section error paths.** These errors are reported at `<root>`, and the message names
  every field involved.
- **Ephemeris coverage.** Epochs are not yet checked against kernel coverage (de440s: 1849–2150).
  The ephemeris provider in M2 must do this.
- **Optimistic defaults.** Several defaults are lossless or unconstrained upper bounds; see
  `docs/model_assumptions.md`, "Optimistic defaults". They are tagged `assumed` and listed by
  `--show-provenance`. Studies must override them.
- **Mutable overrides.** `provenance_overrides` is a `dict` inside a frozen model, so its
  contents are mutable in place. It is never mutated by package code.
- **Python 3.11 not run locally.** Locally only Python 3.12 was exercised. The lock forks for
  3.11 (numpy 2.4.6 / scipy 1.17.1 vs numpy 2.5.4 / scipy 1.18.1 on 3.12+), and that branch is
  covered only by the CI matrix.
- **pre-commit hooks not installed.** `pre-commit install` was not run, to avoid changing
  `.git/hooks` before review.

### Next milestone

M1, the analytic orbit (L0):

- extend `constants.py` with GM☉, c and σ, each with a source;
- add `orbit.py` covering elements ↔ state, Kepler's equation by Newton iteration and two-body
  propagation in Sun-centred ECLIPJ2000;
- add tests for round trips, Kepler-III period and energy and angular-momentum conservation.
